# Eggent 0.2.5 - Light Chats and Model Settings

Date: 2026-09-12  
Type: Patch release snapshot

## Release Name
`Light Chats and Model Settings`

Two screens that asked too much. A new chat carried the entire workspace into
every message before the person had typed anything, and the settings screen that
decides which model answers had become a page of JSON. Both are now sized to the
question being asked.

## What Is Included

### 1) A chat can be opened light

- A new chat saying one word sent **12 797** prompt tokens: 8 775 of tool schemas
  across 31 tools, 945 of the runtime's coding-assistant preamble - whose last
  lines are the path to its own README inside `node_modules` - and 2 990 of
  workspace context. The question itself was 12 of them.
- A chat can now be opened in one of two light modes instead. **Plain chat** is
  the question and the history and nothing else: no tools, and a system prompt of
  nine lines. **Chat and files** adds reading only - `read`, `ls`, and switching
  between projects. Measured the same way: **255** and **712** tokens.
- `ls` is in the reading mode because `read` without it can only open a path
  somebody already knew. Writing, commands, the web, images, messengers,
  schedules and skills are all off, and the light prompt says so, so the agent
  names what it cannot do instead of promising a file it will never produce.
- The mode is chosen when the chat is opened and then belongs to the chat rather
  than to the request: the server reads it from the stored conversation, so
  another tab cannot send the next turn with the whole workspace attached, and a
  light chat answered over a messenger stays light. It is fixed for the chat's
  life, because the cached prompt prefix follows its shape and a history of calls
  to tools that are no longer offered is not worth what it costs at the provider.
- The switch sits in the muted line under the composer that already reports the
  model and the token counts, and is deliberately the quietest control there: a
  menu while the chat is empty, a static label with an explanation once it is
  fixed, and nothing at all on a full chat that can no longer be changed.

### 2) Settings keeps the model up front

- The workspace model screen is provider and model, and nothing else at that
  weight. Thinking level, image generation and the raw `models.json` moved under
  Advanced. A connected provider is one line with Replace key and Disconnect; the
  key field appears only when it is the next step, and a pasted key is cleared
  when the provider changes so it cannot be saved to the wrong one.
- Theme, language and the dashboard login moved to a General tab, saving on
  change.
- Every settings tab that exists per project carries the same project switcher,
  in the same corner, and the choice rides in `?project=<id>` so switching tabs
  keeps the project. `?project=none` is the orchestrator.
- **A project's model is a form, not a file.** The choices are the workspace
  model, or the project's own model from a provider that can serve right now. The
  form states the two runtime rules out loud: while the workspace is on its
  included model every project's `model.json` is ignored, and a saved choice the
  workspace cannot serve falls back to the workspace model. Raw `model.json`
  stays under Advanced and shares state with the form, so neither overwrites the
  other.

### 3) One card can install a set of skills

- A bundled skill may carry a `bundle/` directory. Its children are installed as
  siblings in the project, because the runtime only discovers a skill that is a
  first-level directory under `skills/` - nested, they are invisible and paid for
  in context while doing nothing.
- The siblings are reconciled when the card is reused as well as on first
  install, so a set can gain a skill without anyone reinstalling it, and a
  directory whose name could not be a legal skill name is skipped rather than
  silently ignored later.

### 4) Fixes

- **The model a workspace had saved stopped resolving.** The provider catalog is
  shipped with the SDK and overlaid with a copy refreshed from the network, but
  the overlay was taken only when it looked newer *by mtime* - which npm sets to
  install time, so every freshly built image discarded every refresh. One
  workspace was choosing from 271 of the 445 models its provider serves, and the
  model it had saved was outside that list: the runtime answered on another
  provider's model while both screens reported none was selected. The shipped
  catalogs are dated back at build time and a refresh runs at boot and every four
  hours; `EGGENT_MODEL_CATALOG_REFRESH=0` turns it off. `GET /api/pi/models` also
  reports what is written down beside what actually answers, so a dropped model
  stays in the picker, disabled, under a line naming the model in force.
- **An upload larger than 10 MB arrived cut in half and said nothing.** Every
  request passes through middleware, and such a request is buffered whole against
  a 10 MB default: past it the first 10 MB is kept, the rest dropped, and the
  connection aborted. A 16 MB video dropped into the file tree produced no file
  and no error. The ceiling is now 100 MB and must equal `MAX_UPLOAD_BYTES`, with
  a test that fails on drift; both upload routes refuse by `content-length`,
  naming the size and the limit, before touching a body that is already truncated.
- **An image the agent embedded in a chat drew as a broken box.** A relative
  markdown path resolved against the page address and fetched the dashboard's 404
  page. Relative image paths now go through the file API against the active
  project, decoded first, so a non-ASCII file name is not requested by its
  percent-encoded spelling.
- **A conversation that is loading no longer looks like an empty one.** The
  new-chat screen filled the gap between opening a chat and its messages
  arriving - an invitation to start something, over something already started -
  and on a first load it was in the server-rendered html of every chat opened
  from a link. The transcript now shows its own shape until the messages land.
- **A card with options takes a typed answer.** A question rendered as buttons
  had no input beside them, and an answer routed in from the composer was refused
  as "not available" - so anyone whose answer was not one of the buttons could not
  answer at all.
- **What the agent built can be opened, from anywhere it is named.** The file
  tree gained the Open action the Files page already had, and a file path named in
  an answer is a link when that file exists: an openable type opens rendered in a
  new tab, anything else on its own screen.
- **The workspace has a favicon**, through the framework's own file convention,
  so every page carries it.

## Upgrade Notes

- **Compatibility:** no data migration is required. Chats written before this
  release carry no mode and are read as full.
- **Migration:** none. A project's `model.json` is still honoured; the form is
  another way to write the same file.
- **Operational changes:** the model catalog is refreshed at boot and every four
  hours, which is the only place in the runtime allowed to reach the network for
  it - set `EGGENT_MODEL_CATALOG_REFRESH=0` to turn that off. The upload ceiling
  is 100 MB. Docker still binds to `127.0.0.1` by default.
- **Runtime SDK:** pinned at `0.81.1`. The next four minor versions were
  evaluated and parked; `npm run test:agent-turn` was added for that work and
  runs one real turn - session, custom tool, validated arguments, streamed
  answer - against a local stub, with no network and no credential.

## Verification

- `npx tsc --noEmit`, `npm run lint`, `npm run build`
- `npm run test:agent-turn`, `npm run test:dashboard-routes`,
  `npm run test:project-model`, `npm run test:chat-images`,
  `npm run test:upload-limit`, `npm run test:skill-refresh`
- The three context modes measured through a real session against a local
  OpenAI-compatible stub, reading the request body the provider would have
  received: 12 797, 255 and 712 tokens, and the reading mode's four tools.
- The switcher exercised in a browser against a production build: both
  explanations on hover, the menu, the locked state after the first message, its
  absence on a full chat, and a real turn in plain mode that came back at 220
  prompt tokens.
- The catalog fix reproduced against a workspace's own agent directory in
  throwaway containers, before and after: 271 models to 398, and the saved model
  from unknown to available.
