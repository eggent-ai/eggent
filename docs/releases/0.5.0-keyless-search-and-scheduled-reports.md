# Eggent 0.5.0 - Keyless Search and Scheduled Reports

Date: 2026-10-14  
Type: Minor release snapshot

## Release Name
`Keyless Search and Scheduled Reports`

Web search works without a key and falls through three engines instead of
stopping at the first refusal. A scheduled task sends you what it made, knows
today's date and has enough turns to finish. A public link to a project can
read that project and nothing else. A fresh self-hosted install says how to
sign in, keeps the address it was given and transcribes a `.wav`.

Nothing needs migrating.

## What Is Included

### 1) Search without a key

- `pi-web-access` searched with Exa's keyless endpoint and stopped there when it
  refused; the other keyless engines it ships are used only when named. At start
  the workspace now writes an ordered route into `data/pi-agent/web-search.json`:
  `parallel-mcp`, then `duckduckgo`, then `exa`, falling through on transient,
  quota, network and unreadable answers.
- Exa goes last on purpose: its keyless refusal arrives as an empty result,
  which the extension classifies as `unknown`, and a route stops at a kind it
  was not told to pass over.
- The route depends on the installed extension version. Nothing is written below
  0.24.0 (no Parallel MCP), and 0.24.x gets it without the `unsupported` kind,
  which that version rejects - and a value the extension rejects fails every
  search, not only the route.
- A configuration that names a provider, a key, an endpoint or an allowlist, or
  a search key in the environment, is left exactly as it is. A route written by
  Eggent is updated when the extension changes version and removed if an older
  one comes back.
- `EGGENT_WEB_SEARCH_DEFAULTS=off` turns it off.

### 2) Scheduled tasks

- A scheduled task is two agents: a helper does the work, and the session that
  owns the task writes the report you receive. That report turn used to describe
  the run ("prepared only 3 items") instead of handing over the result. Every
  model call of a report turn now carries guidance after the run's notification -
  sent to the model, never stored - that its reply is the result itself,
  complete and unchanged, and that only a run that produced nothing gets a short
  explanation.
- The run's directive now says to learn today's date first (`date`), not to open
  skill files for more instructions, and that the final answer is what the
  person receives. A morning brief had searched for, and headed itself with,
  yesterday's date.
- A scheduled `Agent` call with `max_turns` below 12 is raised to 12. Models set
  up tasks with 3 or 6, and a run stopped at its limit is wrapped up with half
  the work. An unset limit is left to the extension.
- Tasks stored before this get the current directive and the turn floor the next
  time their store is armed (at start, or when the chat is used).
- "Tell the team: meeting tomorrow at 10" is no longer scheduled for tomorrow at
  10. The runner's note to the model says the message mentions a time, and that
  a time which is part of what to do or say now is done now.
- The extension's pointer "Manage via /agents -> Scheduled jobs", a command of
  pi's terminal interface, is replaced in the tool result by **Settings ->
  Schedules** and `eggent_manage_schedules`, so the agent stops passing it on.

### 3) Public links

- A public link to a project ran with the runtime's whole kit, and staying inside
  the project was an instruction rather than a boundary. It now gets `read`,
  `ls` and search over the project folder, built on file operations that cannot
  reach anything else: nothing outside the folder, nothing hidden, no credential
  file, not the agent's memory or skills, and a link is judged by where it leads.
- Its prompt is the project's instructions and nothing about the workspace.

### 4) First run of a self-hosted install

- The installer's closing lines and the README name the first sign-in:
  `admin` / `admin`, which you are asked to replace at once. It is deliberately
  not shown on the login page, where it would tell any visitor that the stock
  login is still in use.
- An install given another port (`APP_PORT`) gets `APP_BASE_URL` on that port;
  it stayed at `http://localhost:3000`. An address you set yourself is kept.
- A `.wav` sent to speech transcription failed: the upload was saved as
  `<id>.wav` and ffmpeg was asked to convert it onto itself. The converted file
  has a name of its own.
- The Telegram poller is one per process. Next compiles the start-up hook and
  each route separately, so the routes held a copy of their own: the Messengers
  page said polling had stopped while it ran, and its Start button would have
  started a second poller against the first.
- The empty chat promised ready-made paths even where no cards exist; without
  cards it now just asks for a question, a task, a file or a link.

### 5) Smaller fixes

- An image the agent names by its full path in the projects folder
  (`/app/data/projects/...`) is drawn in the chat.
- `proxy-addr` 2.0.8 in the lockfile (GHSA-jqcg-44mw-7w3h, reached through the
  MCP SDK's server dependency; Eggent never runs that server).

### 6) Optional: workspace messages

- A client for a messages service, for deployments that group workspaces: a
  sidebar section, a messages page, a tool for the agent and a copy of received
  files into the workspace. It is loaded only when `EGGENT_MAIL_API_URL` (and a
  token) is set, and the service itself is not part of this repository. Without
  the variable no section, tool, prompt line or background work exists; its
  routes answer that messages are not set up.

## Upgrade Notes

- Compatibility: nothing is removed or renamed. A public link loses tools it
  should not have had.
- Migration: none.
- New, optional: `EGGENT_WEB_SEARCH_DEFAULTS=off`; `EGGENT_MAIL_API_URL`,
  `EGGENT_MAIL_API_TOKEN`.
- Known limits: the keyless engines are rate-limited per address, so many
  installs behind one address can still be refused at the same moment; a search
  key of your own in `web-search.json` avoids it.
