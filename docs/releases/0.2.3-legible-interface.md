# Eggent 0.2.3 - Legible Interface

Date: 2026-08-26  
Type: Patch release snapshot

## Release Name
`Legible Interface`

Every page of the dashboard was measured, then fixed against the measurement
rather than against taste. The result is an interface whose edges are visible,
whose loading states show what is coming, and which can finally say that
something worked.

## What Is Included

### 1) A palette that means something

- The colour system had **one chromatic token and it meant failure**, so the
  product could report an error and had no way to report a success. Eight files
  filled the gap with raw palette utilities - six different greens for one
  meaning, and one five-line function that mixed two colour systems inside
  itself.
- `--success`, `--warning` and `--info` are real tokens now, solved against
  their backgrounds instead of picked by eye: 5.16:1, 4.93:1 and 5.96:1 as text
  on white, with dark-theme values solved against the card. All 68 raw palette
  utilities are gone.
- A semantic colour is never used as text on a wash of itself; that lands near
  the AA threshold from the wrong side. The colour carries the border and the
  text stays at foreground contrast.

### 2) Edges you can see

- Control borders measured **1.26:1** and the keyboard focus ring **1.55:1**
  against the 3:1 that WCAG 2.2 SC 1.4.11 requires, so the boundary of an input
  and the focus indicator were both present and invisible. Both clear it now at
  3.06:1 in light and 3.10:1 in dark; the sidebar's own ring is solved
  separately at 3.08:1 because it sits on a lighter ground.
- The card border is decorative and only had to stop disappearing, so it moves
  to 1.89:1 rather than going heavy.
- Five components painted the corrected ring at half opacity, which put it back
  near 1.5:1. They use the full token.
- Touch targets were 32 to 36px almost everywhere. A 44px minimum applies under
  `pointer: coarse` only, so the desktop interface is not redrawn to solve a
  phone problem, and it covers links, selects and checkboxes rather than
  buttons alone.
- Row actions that appeared only on hover were unreachable by touch and absent
  from the tab order entirely. They fade instead of disappearing, and answer to
  their own row's focus.

### 3) Loading that shows a shape

- Waiting used to be a spinner and the word "Loading" - twice in the file tree
  in hardcoded English at 10px. Schedules, both skills lists and the file tree
  now show the shape of what is coming.

### 4) Motion

- `prefers-reduced-motion` was honoured nowhere in a codebase with 56 spinners.
  It is honoured now, and a spinner **slows rather than freezing**, because a
  loader that stops reads as a hang.
- Three jobs and no more: a page says it arrived (260ms), a turn says it landed
  (300ms), a control answers a press (120ms). Nothing loops and nothing exceeds
  380ms.
- The sidebar stops transitioning `width` and `margin`, which drove layout on
  every frame.

### 5) The front door

- `/login` had **zero** translated strings - an English page on a product that
  ships other languages - and seeded both fields with the default credentials
  on every visit, forever, advertising them on any publicly reachable instance.
  Every string is localized, the prefill is gone, an interrupted session says
  so, and the page states plainly that there is no reset.

### 6) Fixes

- **`/dashboard/projects` never rendered on a full page load.** React streamed
  the resolved subtree into a hidden slot the client never swapped in, so the
  page showed one element with 27 controls present and invisible; navigating to
  it from inside the app always worked, which is why it survived. The Suspense
  boundary was the cause, not the hook.
- Scheduled tasks can be retimed and deleted from the dashboard, through the
  guarded path that takes the lock and re-arms the job. Creating one stays in
  chat, where a scheduled subagent belongs.
- The composer status strip was the only text below 12px.

## Upgrade Notes

- **Compatibility:** no data migration is required.
- **Migration:** none.
- **Operational changes:** none. Docker still binds to `127.0.0.1` by default.

## Verification

- `npx tsc --noEmit`, `npm run lint`, `npm run build`
- Every contrast figure measured by painting the colour to a canvas and reading
  the pixel back, in both themes, with transitions disabled - `oklch` defeats
  naive colour parsing, and a value read mid-transition is a value read wrong.
- Animations confirmed running with their real durations and delays, not merely
  declared in a stylesheet.
- The projects-page fix reproduced on a clean production build before and
  after: 1 visible element becomes 422.
