# Eggent 0.2.7 - Security Update and Uploads

Date: 2026-09-25  
Type: Patch release snapshot

## Release Name
`Security Update and Uploads`

A security update first: the Next.js version 0.2.6 shipped with has two
critical advisories, one of them in an endpoint that every `next start` serves
without a login. With it, a Telegram bot that no longer goes silent when the
model fails, and a way to put files and folders into a workspace without
dragging them, contributed by the community.

**Upgrade promptly.** Nothing needs migrating.

## What Is Included

### 1) Next.js 15.5.26 and patched dependencies

- `next` 15.5.21 to 15.5.26. Two critical advisories covered 15.5.21:
  remote code execution through the image optimizer when it processes AVIF
  files ([GHSA-2xp9-vwfh-vxw4](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4)),
  and remote code execution on Windows-hosted servers
  ([GHSA-p293-qw3h-jr36](https://github.com/advisories/GHSA-p293-qw3h-jr36)).
  The image optimizer answers on every `next start`, and the middleware lets
  `/_next/*` through without a session.
  `sharp` moves to 0.35.4 with it.
- Transitive packages with high advisories are raised within their own ranges:
  `@xmldom/xmldom`, `fast-uri`, `ip-address`, `nanoid`, `postcss`. Beyond
  those and what `next` and `sharp` bring with them, nothing in the lockfile
  moves; a blanket `npm audit fix` would have moved about 170 packages.
- The PDF loader turns off `isEvalSupported`. The PDFs it reads come from
  uploads and from pages the agent fetched, and with eval allowed this pdfjs
  version compiles a font's drawing commands into a function, which is how a
  crafted font runs its own code (CVE-2024-4367). Text extraction needs none of
  it. The major upgrade that fixes it upstream is left for a later release.
- `pnpm-lock.yaml` is gone. The image and the docs install with npm; the file
  had not changed since March, pinned `next` below 15.5.7, and was the source of
  176 of the repository's 226 open dependency alerts. Anyone who installed with
  pnpm got those versions.
- Still open: `pdfjs-dist` below 4.2 (mitigated above) and the `postcss` 8.4.31
  that Next.js pins for its own CSS build.

### 2) Telegram answers a turn that failed

- When the model or its provider failed - a model the provider no longer
  serves, a key it rejects - the Telegram handler rethrew. Polling then ran the
  whole turn twice more and skipped the update; a webhook answered 500 and
  Telegram delivered the update again. Each time through the same broken
  model, while the person saw a bot that had stopped answering and the
  runtime's own explanation ended up in the container log
  ([#26](https://github.com/eggent-ai/eggent/issues/26)).
- A failed turn is now answered once, with the sentence the runtime already
  writes for it (`... does not offer the model ... It offers: ...`), secrets cut
  out and the length capped, and the update counts as handled, so nothing runs
  it again.
- A failure to reach Telegram itself still fails the update and is retried, as
  before.
- `npm run test:telegram-failure` runs the real handler around a stubbed turn:
  the one message, the redaction, no second run of a redelivered update, the
  structured refusal unchanged, and the retry when Telegram is down.

### 3) Upload files and folders without dragging them

Contributed by Sergei Nevzorov ([#23](https://github.com/eggent-ai/eggent/pull/23)).

- Every folder in the Files panel carries two buttons: one opens a file picker,
  the other a folder picker that takes the whole tree underneath it and
  rebuilds it in the workspace. Where the browser has no folder picker (iOS
  Safari) it falls back to files. Until now a file could only get in by being
  dragged onto a folder, and on a touch device there is no drag to make.
- `POST /api/files/upload` takes a `conflict` field: `skip` (the default, and
  the old behaviour) leaves an existing file alone and reports the name back,
  `overwrite` replaces it, `rename` writes `notes (1).md` beside it. The
  dashboard asks before replacing.
- A folder goes up as several requests, each under the 100 MB request limit,
  so its total size is not capped by that limit - only each file in it is.
  Files are streamed to disk rather than buffered a second time.
- An upload never replaces a symbolic link: replacing opens the file without
  `O_EXCL`, which would follow the link to wherever it points.
- The README now notes that a reverse proxy caps request bodies too - nginx at
  1 MB by default - and how to raise it to Eggent's 100 MB.

### 4) A model a provider marks unavailable is shown, locked

- A provider whose model list marks an entry `available: false` - optionally
  with a `note` and a `manage` link - has that model listed after the usable
  ones in the composer picker, the settings page and a project's form,
  disabled, with the provider's note beside it. It never reaches `models.json`,
  so it cannot be chosen, saved or answered with, including after a hand edit
  of the settings file.
- A refused choice shows the provider's note instead of "does not offer", after
  one fresh look at the list.
- Fixed on the way: the agent's `use_provider` switched the included provider
  off and on again when asked for one of its models, which landed on the
  provider's default and still reported success. It now sets the model it was
  asked for, or refuses with the provider's note.

## Platform Coverage

- Dashboard: upload buttons and a folder picker in the Files panel; locked
  models in the picker, the settings page and the project form.
- Runtime: Telegram replies to a failed turn once and does not retry it;
  PDF parsing without eval.
- API: `POST /api/files/upload` gains `conflict` (`skip`, `overwrite`,
  `rename`) and a per-file error `code`.
- Dependencies: Next.js 15.5.26, `sharp` 0.35.4, patched transitive packages,
  no pnpm lockfile.

## Upgrade Notes

- Compatibility: no data migration is required. An upload that does not send
  `conflict` behaves exactly as before.
- Migration: none.
- Operational changes: install with npm; there is no pnpm lockfile any more.
  Behind nginx or another reverse proxy, raise its request body limit to
  100 MB, or uploads over its default fail with `413` before they reach Eggent.
  Docker still binds `127.0.0.1` by default.
