# Eggent 0.7.0 - File History and Pages

Date: 2026-10-25  
Type: Minor release snapshot

## Release Name
`File History and Pages`

Every change to a text file or a document in a project is kept as a version
that says who made it, and can be compared and restored. A web page in a
project opens as it looks, with its blocks to pick for the agent and its words
to change in place, and saves as PDF. Code opens in an editor. A turn no longer
ends as an empty answer.

## What Is Included

### 1) File history

- **What gets a history**: text files and office documents (docx, xlsx, pptx,
  odt, rtf) in a project, up to `EGGENT_VERSIONS_MAX_FILE_MB` (10). Not
  pictures, audio, archives or PDF, not the agent's own bookkeeping files, not
  dependency folders, and never a credential file, a link or a file with a
  second name.
- **A history begins with a file's first change**: what the file held just
  before is kept as the earlier version. A file that was only created, uploaded
  or written by a command gets nothing until it changes.
- **Who wrote it**: before every write - a save in the editor, the agent's file
  tools, an upload that replaces a file, a restore - the current state is kept,
  and after it the new one, signed by the person, the agent (with the chat it
  worked in), an upload or a restore. Files a command names are held in memory
  while it runs and kept only if it changed them. A change made outside Eggent
  (another program, a sync) is noticed before the next write, by the History
  screen and by a pass every `EGGENT_VERSIONS_SCAN_SECONDS` (120).
- **Retention**: every version for `EGGENT_VERSIONS_KEEP_DAYS` (30) after it was
  replaced, then one a day until `EGGENT_VERSIONS_DAILY_DAYS` (90), at most
  `EGGENT_VERSIONS_MAX_PER_FILE` (200) per file. The whole history stays under
  `EGGENT_VERSIONS_MAX_TOTAL_MB` (1024), or `EGGENT_VERSIONS_DISK_SHARE` (0.25)
  of the disk when a deployment reports one; past it the versions replaced
  longest ago go first, never a file. Deleting a file, folder or project frees
  what only it held.
- **The screen**: **History** in the file panel and on a file's page; authors,
  with a link to the agent's chat; a comparison with the previous version, the
  file as it is now or any version, by words (newer wording, older words struck)
  or by lines, with folds and keyboard steps; restore (a new version, never an
  overwrite), download, delete a file's history. Documents are compared by
  their text. A restore that cannot keep what the file holds now asks first.
- **For the agent**: `eggent-history list|show|text|diff <file>`, read-only.
- Settings → General shows the history's size, switches it off and clears what
  is older than a week, or everything. `EGGENT_VERSIONS=off` switches it off for
  a deployment.
- Storage: `data/versions/`, outside every project folder.
- `npm run test:file-versions`.

### 2) Pages and the code editor

- **An HTML file opens as it looks**, in a sandboxed frame that has no origin,
  sends no cookie and can reach nothing on the network; the page and its
  pictures are served under a short-lived token.
- **Pick blocks** on the page to tell the agent which part you mean.
- **Change words on the page**: only those characters are replaced in the
  source, and the change is a version of your own in the file's history. A
  change to the page's structure is put back and refused.
- **Save as PDF**: a print copy stops animations, loads everything in and lets go
  of sticky headers before the dialog opens. Markdown and text print too.
- **Code opens in an editor** (CodeMirror 6, loaded only when needed) with
  highlighting chosen by the file's extension, in the file view and in the side
  panel.
- `npm run test:pages`.

### 3) The open file goes to the agent

- The file open beside the chat, the lines selected in it (up to 4000
  characters) and whether it has unsaved edits are told to the agent with your
  message. It is a note for that turn only: it is not stored in the chat and is
  not read as a scheduling request. The composer says what the agent sees, with
  a cross to take it away.
- The editor offers a newer version written under unsaved edits instead of
  replacing them.

### 4) No empty answers

- A turn stopped in the web chat says so.
- A refusal by the model service after the turn has done some work ends the
  answer with the service's own words, which also come before "no model
  selected" when both apply.
- A turn whose last step wrote no text is asked once more, unseen, to give its
  answer, and says so if it still writes nothing.
- `npm run test:empty-answers`.

### 5) Smaller changes

- Adding a provider records which of its models accept pictures, from the
  provider's own model list.
- A question card shows on a chat whose session was restored at start for its
  schedules.
- The composer waits for a file that is still uploading before it sends.
- The line under a working turn counts the time since anything last appeared,
  and says when the model is still thinking.
- **Telegram**: a bot connects by webhook where `TELEGRAM_MODE` says so (polling
  stays the default, and is used whenever the address is not public HTTPS). A
  webhook is answered at once and its update handled behind it in a queue per
  chat; plain text sent to a busy chat goes straight through, so a stop or
  `/reset` reaches the running turn, and an update that fails is tried three
  times. `npm run test:telegram-webhook`.
- Voice can be transcribed by a provider of your own with an OpenAI-compatible
  transcription endpoint, chosen in Settings → Models → Advanced; local whisper
  remains the default.
- With a deployment's own model service, pictures, voice and the agent's
  look-back at its turns use that service only while the workspace answers on
  it, and each can be turned back on there. `npm run test:eggent-services`.
- Settings → Models on a self-hosted Eggent carries a short card about the
  hosted Eggent with a link to its site. It can be hidden in the browser, and
  `EGGENT_CLOUD_PROMO=0` removes it; a deployment with its own usage provider or
  deployment context never shows it.

### 6) Optional, off unless configured

Each of these needs a service this repository does not include. Without its
variables nothing about it is loaded.

- **The agent's browser** (`EGGENT_BROWSER_API_URL`): a real browser on a
  machine of the deployment's, which the agent drives with `eggent-browser`
  (open, read, click, type, scroll, screenshots, tabs; a password field's value
  is never read back) and you watch live in the Browser panel. Take control to
  sign in, type a code or get past a check: while you have it the agent waits,
  and the panel has an address bar with Back, Forward and Reload that opens web
  pages only. A browser you open yourself starts with control in your hands.
  `npm run test:browser`.
- **Approvals of file versions** (`EGGENT_APPROVALS_API_URL`): in a company
  workspace, a file's current version goes to a chain of people in order; any
  change to the file voids the round, and the next version starts it over. The
  agent can send and read, never approve. `npm run test:approvals`.
- **Files shared inside a company** (`EGGENT_SHARES_API_URL`): the file stays in
  its owner's folder; colleagues see it, comment on a block or on lines, and
  change it if allowed, each change onto the version it was made on and kept
  in the history under its author. `npm run test:shares`.
- **A project run on a coding program of the same computer**
  (`EGGENT_ENGINES_MODULE`): a host module can let a project's turns run on a
  program installed there, with the access level chosen in advance.
  `npm run test:engines`, `npm run test:engines-api`.

## Upgrade Notes

- Migration: none.
- New, optional: `EGGENT_VERSIONS`, `EGGENT_VERSIONS_KEEP_DAYS`,
  `EGGENT_VERSIONS_DAILY_DAYS`, `EGGENT_VERSIONS_MAX_PER_FILE`,
  `EGGENT_VERSIONS_MAX_FILE_MB`, `EGGENT_VERSIONS_SCAN_SECONDS`,
  `EGGENT_VERSIONS_MAX_TOTAL_MB`, `EGGENT_VERSIONS_DISK_SHARE`,
  `EGGENT_CLOUD_PROMO`.
- New dependencies: CodeMirror 6 (editor and languages), `diff`, `parse5`.
- Known limits: the agent's shell can delete `data/versions`; a deleted file's
  history has no screen yet (the agent restores it with `eggent-history`); the
  open file is not told to a turn that runs on the other side of a pair.
