# Eggent 0.2.1 - Published Image and Model Recovery

Date: 2026-08-20  
Type: Patch release snapshot

## Release Name
`Published Image and Model Recovery`

Eggent can now be deployed from a published container image instead of a local
build, and a workspace can always find its way back to a working model. The rest
of this release is the accumulation of fixes since 0.2.0 to the parts people
touch first: connecting a provider, connecting Telegram, and the first hour of a
new workspace.

## What Is Included

### 1) Deployment

- **Published container image.** Releases build and push `ghcr.io/eggent-ai/eggent`.
  `docker-compose.ghcr.yml` runs that image with no build section, so it can be
  pasted into Portainer or dropped on a host on its own. `docker-compose.yml`
  still builds from source for development. linux/amd64 for now.
- **Outbound proxy support.** When `HTTP_PROXY`, `HTTPS_PROXY` or `ALL_PROXY` is
  set, the runtime routes traffic through it and honours `NO_PROXY`. Node's
  global fetch ignores these variables unless told to read them, so a deployment
  behind a mandatory egress proxy previously had nothing working: not provider
  calls, not Telegram polling, not the web tools.
- **Reverse-proxy keep-alive.** The server now outlives an idle connection its
  proxy is still reusing. The symptom was a first message failing with a 502
  while the application log stayed empty, and the retry working.

### 2) Models and providers

- **Coming back to the included model repairs its configuration.** The included
  model is described in `models.json`, which the settings screen lets people
  edit. Losing that entry left a workspace holding a valid credential with no
  model to run it on, with no way back from inside. The switch now rewrites that
  one entry, carries providers you added yourself across untouched, and sets an
  unreadable file aside rather than merging into nothing.
- **A failing provider says what is actually wrong.** Instead of "the model
  returned nothing", the workspace asks the provider's own `/models` and
  separates a dead address from a rejected key from a model id the provider does
  not have - naming the models it does have. Only the OpenAI-compatible dialects
  are probed; the others authenticate differently and would report a good key as
  rejected.
- **The agent can connect a provider itself.** Any OpenAI-compatible endpoint -
  a hosted API, a router, a local model server - needs only a base URL and model
  ids. Keys go to the credential store, never into `models.json`.
- **The settings screen states what is on.** Several paths that could strand a
  workspace with no usable model were closed, and the page's Save button now
  saves the model choice with everything else.
- `?raw=1` returns the models file on disk instead of a fabricated document.

### 3) Telegram and the external API

- **Project switching works.** `switch_project` and `create_project` signals
  were dropped on every run: the runtime stores a tool result inside a wrapper,
  so the parse never matched and the session's project never changed while the
  agent reported that it had. (#19, by @nimph977)
- **An attachment no longer chooses your project.** With no project asked for
  and none remembered, a message carrying a file - or `/start` - used to bind
  the session to whichever project sorted first and persist that choice. Both
  paths now stay in the workspace scope. (#20)
- Delivery survives the request that started it, so a long run still reports
  back.
- Publishing to a channel, and images sent as images rather than as files.
- Connecting a bot completes instead of stalling.

### 4) Schedules

- Scheduled jobs are re-armed when the workspace restarts. Passed one-shots are
  pruned and recurring jobs take their next occurrence.
- Editing a schedule re-arms it, so the stored time and the armed timer agree.

### 5) Workspace and chat

- **The workspace itself has context, memory, skills and MCP**, not only
  projects, so there is somewhere to work before a project exists.
- An empty chat offers a starting point instead of a blank box.
- First run is one step.
- A finished file can be opened in the browser, not only downloaded, served
  sandboxed so built pages cannot run against the dashboard's origin.
- A stopped turn keeps what the agent had already done.
- Consecutive tool calls collapse into one row; links in chat look like links.
- The usage card stops polling when there is nothing to poll or the session is
  gone.

### 6) Internationalisation

- Locale architecture with server-resolved messages. The published build ships
  English.

## Upgrade Notes

- **Compatibility:** no data migration is required.
- **Migration:** none. Sessions that already hold a valid project keep it, so
  the Telegram change moves nobody mid-conversation.
- **Operational changes:**
  - Docker still binds to `127.0.0.1` by default. Use `APP_BIND_HOST=0.0.0.0`
    only when direct public exposure is intended.
  - To run the published image: `docker-compose.ghcr.yml`, with `EGGENT_VERSION`
    to pin a tag.
  - Proxy support needs Node 22.23 or newer. On an older runtime the startup log
    says so and the workspace still starts.
  - Workspace-level context, memory, skills and MCP live in `data/projects/`
    beside the projects.
