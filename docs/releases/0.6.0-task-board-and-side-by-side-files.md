# Eggent 0.6.0 - Task Board and Side-by-Side Files

Date: 2026-10-20  
Type: Minor release snapshot

## Release Name
`Task Board and Side-by-Side Files`

Work can be handed to the agent as cards on a board, each carried out in a chat
of its own. A file opens beside the conversation. A question the agent asks can
be answered by voice or with a file, and one nobody answers for a day no longer
holds its turn. Pipelines are replaced by the board.

## What Is Included

### 1) The task board

- **Board** in the sidebar, `/dashboard/board`. Five columns: inbox, queue,
  working, waiting for you (with the reason: a question, a failure, a stall, a
  stop, a review), done. Archived cards are hidden.
- A card is a chat with a place in a queue: the card's id is its chat's id, and
  the chat shows that it belongs to a card. Writing in a card's chat is followed
  by the card - it shows as working and takes the new result.
- Each card runs through the same runner as every other turn: registered,
  watched for going quiet, stoppable, checkpointed, visible live.
- **The host decides how a card ended**, from how its run ended, never from a
  "done" tool the model has to remember to call: done (the result is the last
  message and the files it made) or waiting for review; a question; a failure,
  retried once after `EGGENT_BOARD_RETRY_SECONDS` (60) and then waiting; a stall;
  a stop; a refusal by the model service, which pauses the whole board until it
  is resumed; a card a restart cut off is resumed twice, then waits.
- A question nobody can answer goes on the card, and the run stops there. The
  answer - a button or text on the card - becomes the next run's message, and
  the card goes ahead of the queue.
- **Start after**: a card can wait for others and starts once they are all done,
  with their results and file paths in its first message.
- **Only the person starts work.** The agent proposes cards with `eggent_board`;
  they land in the inbox, and the agent may change or remove only inbox cards
  (and remove only its own).
- Limits: `EGGENT_BOARD_MAX_RUNNING` (3) and `EGGENT_BOARD_MAX_PER_PROJECT` (1),
  because cards in one project share its folder. `EGGENT_BOARD=off` stops the
  board starting anything.
- Storage: one file per card in `data/board/cards/`, written atomically, with
  credentials masked like chats; board state in `data/board/state.json`.
- `npm run test:board`, `npm run test:board-remote`.

### 2) Pipelines are removed

- They were used by almost nobody and overlapped with the board. Their pages
  open the board, their three tools are replaced by `eggent_board`, and the
  request carries fewer tool definitions.
- Stored pipeline files (`data/pipelines`, `data/pipeline-runs`) are left on
  disk untouched. They are not converted into cards.

### 3) Questions

- **Voice and files.** The answer field under a question card has a microphone
  (not for secrets or command input) and grows with what is typed; the
  paperclip, drop and paste work under a card, and a card can be answered with a
  file alone. `eggent_ask_user` returns the files uploaded since the card opened,
  by path. Options longer than a short label wrap as a list.
- **A question nobody answers for a day ends its turn.** A turn waiting on a
  question was waiting, not stuck, so nothing ever stopped it, and it held its
  chat for as long as nobody came back. Now the wait has a limit,
  `EGGENT_TURN_QUESTION_WAIT_SECONDS` (86400; `0` or `off` for none). The stored
  turn keeps the question and its choices and ends with a line saying it went
  unanswered and can still be answered there; the model is told nobody answered
  rather than that the question was dismissed, so a later message is read as the
  answer. In a card's chat the question goes on the card. A question's wait
  starts when it was asked, and an answer followed at once by the next question
  gives that question a day of its own.
- `npm run test:question-wait`, `npm run test:card-attachments`.

### 4) Files beside the conversation

- A click on a file in the tree, on a path in an answer, on a file in an
  answer's card or on a message attachment opens it in the side panel: text to
  read and edit (Save, Cmd/Ctrl+S, a question before unsaved text is dropped),
  pictures, audio. The panel's width can be dragged and is remembered, and is
  capped so the chat keeps room. **Open full page** still leads to the file's
  own screen.

### 5) Smaller changes

- A project can be created from the sidebar, with the same form as in Settings;
  the new project opens with an empty chat.
- Your own messages sit in a box on the right with their time and a copy button,
  which stays in view on long messages.
- A running turn's progress after an answered question is written to the stored
  chat every finished step (at most every 10 seconds), so a restart in the middle
  no longer leaves the question as the last thing shown.
- A long brief no longer loses the terminal: scheduling words are read only from
  short messages and must share a sentence. The `powershell` tool, which only
  answers on Windows, is hidden elsewhere.
- A scheduled task's helper can send to Telegram and to a colleague (with the
  optional messages client); what it sends is not sent a second time by the
  report.
- An API token generated in Settings no longer locks out the token set in the
  environment; both are accepted.
- Voice can be transcribed by a model gateway that serves
  `/v1/audio/transcriptions`, falling back to local whisper; the microphone
  button shows that it hears.

### 6) Optional: a chat on the other side of a pair

- A workspace and a computer that share its files can also share where a chat
  runs: a message typed on one side for a chat that lives on the other is handed
  over, run there and streamed back, and the board can run a card on either side.
- It needs a relay that this repository does not include, and is switched on
  only by `EGGENT_REMOTE_NODE`, `EGGENT_REMOTE_RELAY_URL` and
  `EGGENT_REMOTE_RELAY_TOKEN` together. Without them a stored place is ignored
  and everything runs where it is typed.

## Upgrade Notes

- Breaking: pipelines are removed (see 2).
- Migration: none otherwise.
- New, optional: `EGGENT_BOARD`, `EGGENT_BOARD_MAX_RUNNING`,
  `EGGENT_BOARD_MAX_PER_PROJECT`, `EGGENT_BOARD_RETRY_SECONDS`,
  `EGGENT_TURN_QUESTION_WAIT_SECONDS`.
- Known limits: cards run inside the workspace process, so a process that is
  stopped stops its cards until it starts again (they are resumed then).
