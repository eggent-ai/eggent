# Eggent 0.2.6 - Model Picker and Files Panel

Date: 2026-09-15  
Type: Patch release snapshot

## Release Name
`Model Picker and Files Panel`

Two controls that were in the wrong place, and one request shape the provider
refuses. The model a workspace answers with could only be changed on a settings
page, the file tree competed with the chat list for one column of height, and
an agent turn carrying tools could not also carry reasoning.

## What Is Included

### 1) The model can be changed from the composer

- The choice lives in the composer row itself, left of send, rather than on a
  settings page you have to leave the conversation for. It is the thing you
  glance at before pressing send.
- It is not a second setting. In a project it writes that project's
  `model.json`; in the orchestrator it writes the workspace default. The
  Models tab shows whatever was chosen there, and the other way round.
- The list is grouped - by family where a provider serves several, by provider
  otherwise - with a search box, because a flat list of sixteen shows about
  five at a time on a laptop.
- The line reports what **will** answer, not what last did. Those differ for
  exactly one turn after a change, and reporting the old one would make the
  control look like it had not worked.
- Below the `sm` breakpoint the name gives way to its icon: with the name
  showing, the text field on a 390px screen came down to 78px, which is not
  somewhere you can type.

### 2) A provider can offer more than one model

- A provider entry in `models.json` can now carry a list of models rather than
  one, and the runtime resolves which of them answers in a single place shared
  by the chat, the settings screen and the project form. Three callers, one
  rule: a screen reporting one model while another answers is the failure this
  avoids.
- A saved model that the provider no longer lists is moved onto the default
  rather than left resolving to nothing.
- Only text models reach the picker. An image or embedding model chosen as the
  chat model breaks every conversation in the workspace, and they arrive in the
  same list; four separate gates refuse it.

### 3) Tools and reasoning in one request

- `/v1/chat/completions` refuses a request that carries both: *"Function tools
  with reasoning_effort are not supported"*. An agent turn always carries
  tools, so a provider entry that declares its models as reasoning ones made
  every message fail.
- Workspaces speak the Responses dialect now (`api: "openai-responses"`), where
  the two coexist. Streaming works there and usage arrives in the final event.
- The chat-completions path keeps a workaround - forcing the effort to `none`
  when tools are present - for an entry that has not been rewritten yet.
  `EGGENT_AI_MODEL_API` pins the old dialect for a deployment that wants it.
- `npm run test:agent-turn-responses` drives a real session against a stub that
  speaks Responses and asserts the request **shape**: `input` rather than
  `messages`, the tool flattened rather than wrapped, a reasoning object beside
  it. The shape is what broke.

### 4) The file tree is a panel of its own

- It moved out of the left sidebar, where the project list, the tree and the
  chat history competed for one column of height and a deep folder pushed the
  conversations off the screen. It opens from the header instead.
- Closed it takes no width at all rather than collapsing to a rail: a strip
  that narrow has nothing useful to show.
- On a phone it comes over the chat with a dimmed backdrop. Hiding it below
  `md` was the first cut and it took the file tree away from phones entirely.
- It is mounted on every screen that carries the header, not just the chat: the
  button lives in the header, and a button that does nothing on four of seven
  pages is worse than no button.
- Its height comes from the viewport and it sticks. Taken from the row it sits
  in, the panel ended wherever the page's content stopped - on the file view,
  mid-list.
- The tree marks the open file as well as the current directory. It marked only
  directories, so clicking a file navigated away and left nothing highlighted.

### 5) Runtime SDK 0.85.1

- Four minor versions in one step, from `0.81.1`. The breaking ones are 0.83,
  where TypeBox drops deprecated APIs this code never called, and 0.84, where
  `message_update` carries deltas only - the form the chat runner, the pipeline
  runner and the schedule host already read.
- `npm run test:agent-turn` and `test:agent-turn-responses` each drive a real
  session against a local stub, with no network and no credential.

## Platform Coverage

- Dashboard: the composer model picker, the files panel, the collapsed model
  select showing a name rather than a clipped sentence.
- Runtime: a provider with several models, one resolution rule, the Responses
  dialect, SDK 0.85.1.
- API: `PUT /api/projects/<id>/model` accepts a model of the current provider
  instead of refusing outright while a provider is fixed.

## Upgrade Notes

- Compatibility: no data migration is required. A provider entry with a single
  model keeps working exactly as before.
- Migration: none. A workspace whose saved model no longer resolves is moved
  onto the provider's default at boot.
- Operational changes: workspaces now speak the Responses dialect by default;
  `EGGENT_AI_MODEL_API=openai-completions` restores the previous one without a
  rebuild. Docker still binds `127.0.0.1` by default.
